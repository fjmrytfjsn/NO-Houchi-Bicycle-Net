NO-Houchi Bicycle Net

放置自転車対策における地域参加型・運用統合フローの提案

所属 / チーム D2 / D²(ディースクエアード)
発表者 伊藤航希・大久保慈人・岡田理玖・柴田悠翔・藤村勇仁・道下大夢
要旨

本提案の主目的は、通報から回収結果記録までの運用を一元化し、回収業務の空振りと分断を減らすことである。 持ち主の自発的移動は、回収対象を減らす副次的効果として位置づける。

1. Background

背景

都市部の放置自転車は、歩行空間の安全性低下、景観悪化、店舗前環境の阻害を引き起こす。 行政や委託事業者は巡回、警告、回収、記録に継続的な負担を抱えている。

  • 駅前や商業地で放置自転車が発生しやすい
  • 歩行者動線と店舗前空間の確保が課題となる
  • 対応コストが行政側に偏りやすい

2. Problem

問題設定

01

タイムラグ

発見から行政側の状況把握までに時間差がある。

02

運用の分断

通報、警告、回収依頼、結果記録が別々に扱われやすい。

03

空振りの発生

現地確認や回収時に対象が存在しないケースが起こる。

04

履歴の分散

案件の経過が一元管理されず、運用改善へつながりにくい。

3. Objective

研究目的

放置自転車対応を一連の統合運用フローとして扱う仕組みを設計し、 通報から回収結果記録までの一元化によって回収運用の効率化が可能かを示す。

  • 案件管理の一元化
  • 回収フローの明確化
  • 自己解決導線の補助的活用

4. Proposed System

提案システム

Supporter App

写真・位置情報・識別情報付きで現地通報を行う。

Owner Web

QRから警告確認、仮解除、本解除を実行する。

Admin Dashboard

案件確認、回収依頼、結果記録を行う。

Backend API

状態遷移と履歴を一元管理し、各クライアントを接続する。

通報 案件管理 回収依頼 結果記録

5. Integrated Workflow

統合運用フロー

主軸は回収フローの統合・効率化であり、持ち主対応はその途中で回収対象を減らす分岐として扱う。

主フロー
1

通報

サポーターが写真・位置情報・識別情報を送信

2

案件管理

バックエンドで案件登録し、管理者が一覧管理

3

回収依頼

未対応案件を回収対象として業務フローへ投入

4

結果記録

回収完了または現地で現物なしを記録

副次分岐

持ち主確認

QRから警告内容を確認

仮解除 / 本解除

自発的移動が行われた場合は回収不要

状態遷移

`reported → collection_requested → collected / not_found_on_collection`

`reported → temporary → resolved`

6. Key Features

試作システムの特徴

  • 通報から回収結果までを同一フローで追跡できる
  • 管理者が回収対象案件を把握しやすい
  • 持ち主対応を回収前分岐として組み込める
  • 行政運用を中心に据えつつ地域参加を取り込める

7. Expected Effects

期待される効果

行政

回収依頼対象の把握、空振り削減、履歴管理の効率化。

住民

歩行環境と景観の改善。

持ち主

撤去前に対応できる機会の提供。

地域店舗

将来的な地域循環や来店導線への接続可能性。

8. Scope

試作範囲

対象

  • 通報
  • 警告確認
  • 仮解除 / 本解除
  • 回収依頼
  • 結果記録

対象外

  • ブラックリスト管理
  • 高度分析
  • 保管返還管理
  • 外部システム本連携

本試作は、統合運用フローの成立確認を主目的とする。

9. Future Work

今後の展望

  • 実証を通じた運用効果の評価
  • 自己解決率の検証とUI/UX改善
  • 地域協賛と分析機能の具体化
  • 不正対策や外部連携への拡張

10. Conclusion

まとめ

放置自転車対策の主課題を回収運用の分断と捉え、その統合を目的とした試作システムを提案した。 持ち主対応は補助的導線として組み込みつつ、中心には回収フローの一元化と効率化を据えている。
